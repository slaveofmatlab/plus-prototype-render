# 商品匹配 - 核心功能文档

## 1. 功能目标

输入一条订单商品名称，从公司标准商品库中匹配出最相似的标准商品及编号，按评分从高到低返回候选列表。

---

## 2. 环境安装

项目根目录"Product_Price_Recommendation"下提供了一键依赖文件，执行：

```bash
pip install -r requirements.txt
```

---

实现单条匹配功能所需的文件（按依赖顺序）：

**预处理阶段**（将原始商品表转为商品库）：

|------|------|------|

## 4. 完整使用流程

从原始商品表到完成一次匹配，完整步骤如下：

### Step 1：安装依赖

```bash
cd "Product_Price_Recommendation"(自己的路径)
pip install -r requirements.txt
```

### Step 2：预处理商品库

将从丰厨平台导出的原始商品表预处理为匹配算法可用的商品库：

```bash
cd "Pre-process\Product_Normalizer2.0"
python run_normalizer.py ../../Database/RSM_723.xlsx
```

输出文件自动生成在 `Database/` 目录，文件名固定为 `处理后标品库.xlsx`。

### Step 3：调用匹配函数

```bash
cd "Matching Algorithm"
```

```python
from service import get_matcher

# 自动加载最新商品库（首次调用时初始化）
matcher = get_matcher()

# 执行匹配
results = matcher.query("五得利五星特精小麦粉25kg", top_n=5)

for r in results:
    print(f"{r['rank']}. {r['标准产品名称']}  编码:{r['标准产品编码']}  得分:{r['score']}")
```

输出：
```

2. 五得利四星特精小麦粉25kg  编码:1002  得分:1.1023
3. 五得利三星特精小麦粉25kg  编码:1003  得分:0.9812
...
```

### Step 4（可选）：启动 Web 界面


## 5. 预处理输入输出说明

**输入要求**：原始 Excel 必须包含 `商品名称` 列。名称含"禁用"的记录会被自动跳过。

**输出**：预处理后的商品库包含以下列，供匹配算法直接使用：

| 输出列 | 说明 |
|--------|------|
| `标准产品名称` | 原始标准品名 |
| `标准产品编码` | 商品编号 |
| `core_tokens` | 核心分词结果（用于 BM25 召回） |
| `core_name` | 去品牌/规格后的核心名称（用于 bigram 召回） |
| `detected_brand` | 识别出的品牌 |
| `normalized_spec` | 标准化规格 |
| `attributes` | 属性词列表 |

## 6. 调用匹配函数

### 6.1 初始化

```python
from matcher import ProductMatcher

matcher = ProductMatcher("Database/处理后标品库.xlsx")
```

或使用 service 层自动定位最新商品库：

```python
from service import get_matcher

matcher = get_matcher()
```

### 6.2 查询

```python
results = matcher.query(query_text, top_n=10, recall_size=200)
```

**参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `query_text` | str | 必填 | 用户订单商品名称 |
| `top_n` | int | 10 | 返回结果条数 |
| `recall_size` | int | 200 | 召回候选池大小 |

### 6.3 返回结果

返回 `List[Dict]`，按得分降序排列，第一项为最佳匹配。每一项结构：

```python
{
    'rank': 1,                          # 排名
    'score': 0.8732,                    # 综合得分
    '标准产品名称': '五得利五星特精小麦粉25kg',
    '标准产品编码': '1001',
    'detected_brand': '五得利',          # 品牌
    'normalized_spec': '25kg',          # 规格
    'core_name': '小麦粉',              # 核心名称
    'attributes': ['五星', '特精']       # 属性列表
}
```

## 7. 控制返回列表数量

通过 `top_n` 参数直接控制返回条数：

```python
# 只取最佳 1 条
results = matcher.query("海天金标蚝油520g", top_n=1)

# 取 Top 5
results = matcher.query("海天金标蚝油520g", top_n=5)

# 取 Top 50（扩展召回，recall_size 也相应增大）
results = matcher.query("海天金标蚝油520g", top_n=50, recall_size=500)
```

也可以使用快捷方法 `query_extended()`，默认返回 50 条：

```python
results = matcher.query_extended("海天金标蚝油520g")  # 等同于 query(..., top_n=50, recall_size=500)
```

## 8. 匹配流程概述

`query()` 内部执行以下步骤：

```
用户输入 → 预处理（品牌/规格/属性识别 + 分词）
         → 二路召回（BM25 + 字符2-gram，取并集）
         → 品牌粗筛（同品牌候选 ≥ 5 条时仅保留同品牌）
         → 重排评分
         → 返回 Top-N
```

**重排评分** = 语义基础分 + 规格加分 + 属性加分 + 品牌加分 + 散称加分：

| 分量 | 规则 |
|------|------|
| 语义基础分 | BM25×0.6 + bigram×0.4（归一化后） |
| 规格加分 | 数值+单位匹配 +0.5 / 仅数值匹配 +0.4 / 数值冲突 -0.1 |
| 属性加分 | 命中比例 × 0.15 |
| 品牌加分 | 品牌对应 +0.35 |
| 散称加分 | 订单无规格时，散称候选 +0.3 |

## 9. 匹配置信度评估

除排序得分外，可对每条候选单独计算置信度（0~1），用于判断匹配是否可信：

```python
from normalizer.main import process_single_record

query_text = "五得利五星特精小麦粉25kg"
query_info = process_single_record(query_text, brands_sorted=matcher.brands)
results = matcher.query(query_text, top_n=5, query_info=query_info)

for r in results:
    conf = ProductMatcher.compute_confidence(query_info, r)
    print(f"{r['rank']}. {r['标准产品名称']}  得分:{r['score']}  置信度:{conf}")
```

置信度基于三个维度（品牌仅当订单或候选有品牌时参与，规格仅订单有规格时参与，权重按参与维度自动归一化）：

| 维度 | 权重 | 高分条件 |
|------|------|----------|
| 品牌对应 | 0.25 | 品牌匹配（互相包含）→ 1.0；订单无品牌结果有品牌 → 0.8；订单有品牌结果无品牌 → 0.1；不一致 → 0.0 |
| 规格对应 | 0.25 | 数值+单位匹配 → 1.0；数值匹配单位不同 → 0.7；结果无规格 → 0.2；数值不一致 → 0.5 |
| 核心名相似度 | 0.5 | 字符 bigram 的 Dice 系数（0~1） |

> 注意：`score` 用于排序，`confidence` 用于评估可信度，两者独立计算，不可直接比较。

---

## 10. 注意事项

1. **规格误匹配风险**：规格加分是固定大额加分，当商品库无对应品时可能"同规格不同品"（如"梨汁1kg"匹配到"鸡汁1kg"）
2. **品牌加分仅对库内品牌生效**：订单品牌不在商品库中则所有候选无品牌加分
3. **品牌粗筛安全阈值**：同品牌候选不足 5 条时自动放弃过滤，防止漏召回
4. **`query_info` 复用**：批量处理时外部可先统一预处理，再传入 `query_info` 避免重复计算
5. **商品库更新后需重启**：修改原始数据后需重跑 `run_normalizer.py` 并重新初始化 matcher
