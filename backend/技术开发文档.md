# 报价建议 Demo - 技术开发文档

## 一、项目概述

### 1.1 目标
构建一个前后端分离的报价建议演示系统，用户上传客户询价单（Excel），系统自动匹配标准商品库，展示匹配结果并支持人工校正，最终查询历史报价信息。

### 1.2 核心业务流程
上传询价单 -> 解析商品列表 -> 逐条匹配标准商品库 -> 展示匹配结果（含置信度）
-> 用户可通过下拉框切换备选匹配 -> 按置信度筛选
-> 确认商品后查询历史报价 -> 展示报价信息（单价/运营公司/客户名称/报价时间）

---

## 二、技术架构

### 2.1 技术栈选型

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| 前端 | React 18 + Vite + Ant Design 5 | Ant Design 提供成熟的 Table/Form/Select 组件，适合表单密集型应用；Vite 热更新快，支持快速迭代 |
| 后端 | Python FastAPI | 与现有匹配算法同语言，可直接调用；异步支持好 |
| 数据解析 | pandas + openpyxl | 项目已有依赖，处理 Excel 文件 |
| 匹配算法 | 现有 Matching Algorithm/matcher.py | BM25 + 2-gram 双路召回，不修改源码，直接 import 调用 |
| 报价数据 | 报价数据总表.xlsx | 按产品编码查找历史报价 |

### 2.2 系统架构

前端(React+Vite) --HTTP REST API--> 后端(FastAPI) --调用--> 匹配算法 + 报价数据

前端组件：文件上传 | 匹配结果表单(含备选下拉) | 置信度筛选器
后端模块：文件解析 | 匹配服务 | 报价查询服务

## 三、功能模块详细设计

### 3.1 模块一：文件上传与解析（后端）

职责：接收用户上传的 Excel 询价单，解析出商品列表。

API: POST /api/upload
- 自动检测含商品名称的列
- 支持 .xlsx 和 .xls 格式
- 返回 task_id + 商品列表

### 3.2 模块二：商品匹配服务（后端）

职责：对解析出的商品列表逐条调用现有匹配算法。

API: POST /api/match
- 调用 matcher.query(raw_name, top_n=10)
- 返回每条商品的最佳匹配 + 备选列表 + 置信度

调用方式：通过 service.py 的 get_matcher() 获取单例

### 3.3 模块三：备选结果切换（后端）

职责：用户在下拉框中选择备选匹配时，更新确认结果。

API: POST /api/select_alternative
- 更新该条目的 confirmed_match
- 自动触发报价重新查询

### 3.4 模块四：报价数据查询（后端）

职责：根据确认的产品编码查找历史报价。

API: POST /api/quote_lookup
- 按产品编码在报价数据总表中查找
- 返回：单价、采购价、运营公司、客户名称、报价时间、有效期

数据加载：启动时建立编码索引，O(1) 查找

### 3.5 模块五：前端 - 文件上传页面

组件：FileUpload.tsx
- Ant Design Upload.Dragger 拖拽上传
- 解析完成后自动跳转匹配结果页

### 3.6 模块六：前端 - 匹配结果表单

组件：MatchResultTable.tsx

表格列：序号 | 询价商品名 | 匹配商品编码 | 匹配商品名称 | 置信度 | 备选匹配(下拉框) | 历史报价(单价) | 报价时间 | 运营公司 | 客户名称

置信度筛选：Slider 组件选择区间，本地实时过滤

## 五、关键设计决策

1. 不修改匹配算法源码，通过 sys.path.insert 直接调用
2. Ant Design 组件化，新增列只需修改 columns 配置
3. 匹配算法单例预加载，报价数据建索引，保证响应速度
4. 置信度筛选在前端本地完成，无需网络请求
5. 后端内存字典管理状态，Demo 场景无需持久化
