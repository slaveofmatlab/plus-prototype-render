# Database 文件夹说明

## 一、功能概述

Database 文件夹存储**标准产品库**，是整个商品价格推荐系统的匹配基础。匹配算法基于预处理后的商品库进行产品相似度匹配。

---

## 二、文件结构

### 初始文件（原始产品库）

从**丰厨平台**导出的「标准商品信息」表单，包含「标准产品名称」列及分类、编码、规格等原始字段。

| 文件 | 说明 |
|------|------|
| `RSM_723.xlsx` | 丰厨导出的标准产品库（32674 条，含"禁用"记录需在预处理时跳过） |

### 预处理后文件

经 Pre-process 模块处理后的文件，命名格式为 `<原文件名>_normalized_<时间戳>.xlsx`：

| 文件 | 说明 |
|------|------|
| `RSM_723_normalized_20260807_175602.xlsx` | 预处理后的产品库（32514 条，已跳过"禁用"记录） |

> 每次运行预处理会生成新的带时间戳文件，保留历史版本。

---
## 三、使用流程

```
丰厨导出标准产品库
       │
       ▼
  Pre-process 预处理
       │
       ▼
  Database/ 中生成 _normalized_ 文件
       │
       ▼
  匹配算法基于预处理后的商品库进行匹配
```


## 四、预处理流程简述

Pre-process 模块对「标准产品名称」依次执行以下处理：

1. **品牌检测**：识别并提取品牌名（如"味达美牌"→"味达美"）
2. **文本标准化**：全角转半角、单位统一（1L→1000mL）、品牌摘除、括号处理等
3. **智能分词**：基于领域词库 + 动态规划 + jieba 兜底进行分词
4. **规格分离**：提取规格信息，生成去品牌去规格的核心产品名
5. **属性识别**：基于属性词表识别国家、加工方式、品质等级等属性

> 详细处理流程请查看 [Pre-process 模块说明](../Pre-process/Pre-process模块说明.md)。

---

## 五、预处理新增字段

预处理后在原表「标准产品名称」列之后插入 8 列：

| 列名 | 说明 | 示例 |
|------|------|------|
| `normalized_name` | 标准化后完整名称 | 味极鲜酱油1000mL/瓶 |
| `tokens` | 全量分词（含品牌+规格） | ["味达美","味极鲜","酱油","1000mL","瓶"] |
| `detected_brand` | 识别到的品牌 | 味达美 |
| `core_name` | 去品牌去规格的核心产品名 | 味极鲜酱油 |
| `raw_spec` | 原始规格 | 1L 瓶 |
| `normalized_spec` | 标准化规格 | 1000mL 瓶 |
| `core_tokens` | 核心产品 tokens（匹配算法主要依据） | ["味极鲜","酱油"] |
| `attributes` | 识别到的属性词列表 | ["非转基因", "一级"] |

其中 **`core_tokens`** 是匹配算法的核心依据，用于计算产品间的相似度。
